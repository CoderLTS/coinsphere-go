# CoinSphere 开发计划

本文只维护稳定的能力顺序和完成标准。当前分支、PR、Issue、完成状态和验收证据以 GitHub 为准。

## 目标

CoinSphere 以工作流为核心，为个人用户提供可观察、可回放的低频量化闭环：行情进入系统后，由工作流连接策略、信号、通知和 Paper 执行；私有交易能力始终在独立门禁之后。

```mermaid
flowchart LR
    BASE["独立部署基线"] --> FLOW["工作流体验"]
    FLOW --> RESEARCH["行情与策略研究"]
    RESEARCH --> PAPER["Paper 运行证据"]
    PAPER --> PRIVATE["Testnet / Live 放行"]
```

## P0 独立部署基线

结果：单一初始化 migration、独立 `coinsphere-go` Compose、独立 TimescaleDB、Web + Go App + 双槽位 Worker 默认拓扑。

完成标准：

- 空库可执行 Up、重复 Up、空库 Down 和重新 Up。
- 默认部署不启动旧 Paper Executor、第二个 Worker 或 Private Executor。
- 发布只移除旧 CoinSphere 容器，不操作 sub2api 或其他共享服务。
- 固定 digest 部署、健康检查和上一版本回滚可执行。

## P1 工作流体验

结果：保留首页运行概览，用户从独立工作台完成创建、连线、配置、运行、审批和排障，不需要跨多个后台页面拼接状态或手写 JSON/状态路径。

完成标准：

- 手工、定时和领域事件触发都可在画布定位到执行记录。
- 节点和边清晰显示 pending/running/success/failed、耗时和错误。
- Graph V2 数据端口、Owner 隔离、取消、整次重跑、Worker 等待和人工待办契约稳定。
- 当前业务、配置和安全任务均有显式注册的领域节点，高风险扩大动作要求人工确认与重新认证。
- 桌面端完成拖拽编辑；移动端完成查看、回放、运行和处置；亮色与暗色主题完成用户视觉验收。

## P2 行情与策略研究

结果：元数据、K 线、策略版本、回测和实时信号形成可复现研究链路。

完成标准：

- Binance Spot/USD-M 元数据按设置过滤，每小时或手工同步。
- 闭合 K 线完整、UTC 对齐、重复写入幂等，断线补数可验证。
- 回测与实时计算复用同一策略入口和 Decimal 规则。
- K 线页面可查询单策略目标仓位和 BUY/SELL/FLAT 信号。

## P3 Paper 运行证据

结果：Paper 账户在真实运行周期中证明信号、风控、意图、成交和投影可恢复。

完成标准：

- 急停、权限、账户暂停、行情过期和全部风险上限均能阻断新增风险。
- 意图、订单、成交、费用和持仓投影可幂等重放。
- Worker、Go App 或主机重启后没有重复信号、重复意图或无法解释状态。
- 用户确认观察期和证据满足下一阶段要求。

## P4 私有交易放行

结果：按 `Testnet -> Live manual -> Live auto` 顺序逐级启用 Private Executor。

完成标准：

- 每一级分别完成凭据、确定性订单、未知状态恢复、保护单、对账和急停演练。
- 不存在未解释的外部订单、仓位、手续费或资金费差异。
- 管理员授权、Owner 放行、账户状态和硬风控同时有效。
- 用户在当前任务明确批准目标环境；代码合并和部署不自动放行。

## 非目标

- 高频交易、多交易所套利、多实例集群和任意后端插件。
- Redis、消息中间件、Kubernetes 或第二套策略模型。
- 由 CI、Codex、工作流或通用 HTTP 节点接触真实密钥或发起真实订单。
