# CoinSphere 路线图

## 产品方向

CoinSphere 从现有通用后台与工作流系统演进为个人自托管的 Binance 低频量化平台。目标是先完成可复现研究，再逐级增加信号、人工确认、Paper、Testnet 和小额实盘；代码合并不等于获得任何交易权限。

本目录只记录稳定能力依赖和退出条件。当前进度、分支、PR、Milestone、Issue 和验收证据以 GitHub 为唯一来源，不在仓库维护状态副本或完成百分比。

## 能力依赖

```mermaid
flowchart LR
    G["治理重置"] --> API["原子 /api/v1 与登录边界"]
    API --> DATA["Binance 行情"]

    RESEARCH --> SIGNAL["实时信号、通知与批准"]
    SIGNAL --> PAPER["Paper 执行与投影"]
    PAPER --> TESTNET["Spot / USD-M Testnet"]
    TESTNET --> SPOT["Spot 小额实盘"]
    SPOT --> FUTURES["USD-M 小额实盘"]
```

## 里程碑

| 里程碑          | 稳定结果                                              | 退出条件                                             |
| --------------- | ----------------------------------------------------- | ---------------------------------------------------- |
| M1 研究闭环     | 治理、`/api/v1`、Binance 行情、单文件策略和确定性回测 | 契约、数据质量和回测黄金案例通过                     |
| M2 信号闭环     | 实时信号、内嵌通知、移动端批准、Paper 和事件投影      | 两秒延迟目标、权限隔离、投影重建和安全演练通过       |
| M3 Testnet 闭环 | Spot 与 USD-M Testnet 执行、保护单、恢复和对账        | 无未解释差异；幂等、未知状态、止损失败和急停演练通过 |
| M4 小额实盘     | Spot 手动/自动，再到 USD-M 手动/自动                  | 每一级证据完整，并由用户手工放行                     |

## 放行规则

- 放行顺序固定为 `Paper -> Testnet -> Live manual -> Live auto`；Spot 实盘先于 USD-M 实盘。
- 不使用固定“30 天/100 单”作为替代证据。每次晋级必须完成适用的恢复、幂等、对账、保护单和急停演练，且不存在未解释差异。
- 自动模式同时要求管理员授权、用户启用和完整账户风控；缺少任一条件时保持禁用。
- 真实交易和生产部署只能由用户手工触发。CI、Codex、工作流和通用 HTTP 节点不得接触真实密钥或发起真实订单。
- 首轮范围以 [架构概览](../architecture/overview.md)、[公共契约](../contracts/README.md) 和 [实施计划](./implementation-plan.md) 为准；未列入的能力不提前搭建入口或兼容层。
