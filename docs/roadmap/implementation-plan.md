# CoinSphere AI 全流程实施计划

- 状态：已接受，执行中
- 更新日期：2026-08-01
- 交付方式：Codex + GPT 5.6sol
- 产品负责人和最终放行人：用户

## 1. 交付与治理

项目由 Codex 使用 GPT 5.6sol 完成需求细化、架构设计、实现、测试、文档、排障和发布产物制作。用户负责产品方向、高风险取舍、PR 审查、GitHub 与家用 Linux 配置、生产凭据注入、手工合并和阶段放行。

必须遵守以下边界：

- Codex、GitHub 和 CI 永不接触真实交易所密钥或发起真实订单；允许用户手工触发受 `production` Environment 约束的发布工作流连接生产主机并自动部署。
- `main` 开启分支保护，禁止直接提交和自动合并。
- 分支使用 `codex/<issue-id>-<slug>`；每个 PR 只交付一个可独立验收和回滚的行为。
- 数据库迁移、凭据、风控和订单状态机使用独立 PR，并提供回滚说明。
- 每个 PR 必须描述目标、非目标、设计、迁移影响、验证结果、界面证据、风险和回滚。
- 实现完成后使用新的只读上下文复审回归、安全边界和测试缺口。
- 需求、ADR、API 契约、测试和代码是事实来源，聊天上下文不能成为唯一设计依据。
- Renovate 每周创建依赖 PR，所有依赖更新均由用户审查并手工合并。

## 2. 产品范围

### 2.1 核心范围

- Binance 与 OKX 双交易所。
- 现货、USDT 永续逐仓双向持仓。
- 内置模拟盘；实盘按模拟盘、小额现货、USDT 永续顺序放行。
- vectorbt 1.1.0 向量回测与 NautilusTrader 1.230.0 事件回测。
- Monaco 多文件 Python 策略编辑器。
- PostgreSQL/TimescaleDB 在线数据和不可变 Parquet 数据集。
- 中英双语新闻与版本化 LLM 情绪、相关度和事件因子。
- 保留 RBAC、AI 助手、通知和工作流，不建设 SaaS 多租户、计费或开放注册。

### 2.2 首轮非目标

- 逐笔成交、完整盘口和高频交易。
- 跨交易所套利和多标的组合优化。
- 币本位、全仓、复杂清算模拟。
- OCO、TWAP 等高级算法单。
- AI 自主交易或绕过风控的自动执行。

## 3. 目标架构

### 3.1 运行边界

- Go 保持模块化单体，领域模块为 `marketdata`、`dataset`、`news`、`strategy`、`backtest`、`trading`、`risk`、`workflow`、`platform`。
- 同一 Go 代码库构建 `api`、`collector`、`executor`、`scheduler` 四种进程。
- Python 3.12 Worker 独立容器运行数据集生成、vectorbt 与 NautilusTrader。
- PostgreSQL `FOR UPDATE SKIP LOCKED` 实现任务队列，事务 Outbox 实现可靠事件；首版不引入 Redis、Kafka 或 NATS。
- TimescaleDB 保存在线行情和业务状态，共享卷保存 Parquet、策略包、日志与回测产物。
- Binance 使用官方 Go Connector；OKX 使用官方 REST/WebSocket 协议的薄适配器。
- 工作流只编排补数、数据集、批量回测、报告和通知，不参与逐 K 线计算或下单。
- 家用 Linux 使用 Docker Compose `research`、`paper`、`live` Profile，只允许 LAN 或 Tailscale/WireGuard 私网访问。

### 3.2 不可破坏的契约

- 时间统一使用 UTC `timestamptz` 和 RFC3339Nano。
- 价格、金额、数量和费率使用 Decimal 与 `numeric(38,18)`，禁止账务使用 `float64`，JSON 使用字符串。
- 新金融 API 位于 `/api/v1`，金融 ID 使用 UUIDv7，列表使用游标分页。
- 命令接受 `Idempotency-Key`；错误使用 `application/problem+json`。
- WebSocket 信封固定为 `{type,version,sequence,occurredAt,data}`。
- 策略为“可编辑草稿 + 不可变发布版本”，回测、模拟和实盘只能引用发布版本。
- 数据集包含不可变 Manifest、内容哈希、分区校验和、质量报告和来源修订号；被引用后禁止覆盖。
- 模拟与实盘账户、凭据、订单、仓位和风控状态强逻辑隔离。

## 4. 分阶段实施

### A0 工程系统

目标：建立所有后续金融代码必须经过的工程治理和可重复验证入口。

独立交付顺序：

1. 规则、路线图、架构总览、ADR、契约、PR/Issue 模板、本地验证脚本与 Go/Vue/Python 基础 CI。
2. 清理现有前端 Stylelint 基线，将 Stylelint 设为阻塞检查。
3. 已建立版本化 SQL migration 工具，以及空库升级、旧版本升级、回滚重放、幂等和失败原子性测试骨架；A1 再切换应用启动路径。
4. 建立关键 Playwright 冒烟、Worker 容器、Compose 健康测试和 API 冒烟。
5. 建立 Gitleaks、govulncheck、pip-audit、Trivy 镜像扫描、SBOM、校验和与 GHCR 发布流水线。
6. 用户配置远程仓库、分支保护、Actions 权限和 Renovate App。

当前进度：Python Worker 容器及开发 Compose/CI 健康门禁已经建立，Worker 保持无任务消费能力的 `a0-idle` 模式；关键 Playwright 场景仍待后续独立 PR 完成。

退出条件：所有 A0 检查在干净 checkout 可复现，分支保护实际生效，发布产物不包含凭据，回滚手册经过桌面演练。

### A1 基础稳定化

目标：先消除现有通用平台中会放大金融风险的并发、认证和安全缺陷。

独立交付顺序：

1. 全链路 Context 取消、超时、信号处理与优雅关机。
2. Worker 租约、心跳、崩溃回收和 5 秒内任务取消。
3. Outbox 锁租约、指数退避、最大重试、死信和告警。
4. 工作流版本生成与激活事务化，覆盖并发和中间状态测试。
5. WebSocket 单写协程、心跳、背压、序列号和严格 Origin。
6. HTTP 节点 SSRF 防护、私网阻断、域名白名单、重定向复检和 Header 脱敏。
7. Access Token 内存保存，Refresh Token 安全 Cookie、轮换和自动刷新。
8. 关闭注册和找回密码，增加管理员初始化与离线重置命令。
9. Mermaid 严格模式、内容清洗和 CSP。
10. 移除生产 AutoMigrate，完成版本化 SQL migration 切换。
11. 结构化日志、请求 ID、Prometheus、审计事件、存活和就绪检查。

退出条件：竞态测试通过；取消、崩溃回收、Outbox 死信、Auth 轮换、SSRF、XSS、WebSocket 背压和关机均有自动化测试。

### A2 行情底座

目标：获得可持续运行、可修复并可量化质量的双所行情事实源。

独立交付顺序：

1. TimescaleDB schema、版本迁移、Decimal/UTC 公共类型和交易所品种模型。
2. Binance 公共连接器与全量品种元数据同步。
3. OKX 公共连接器与全量品种元数据同步。
4. 安装时固定 BTC、ETH，并推荐双所共同品种中 30 日 USDT 成交额最高的另外 18 个。
5. 1m OHLCV 实时采集、唯一键去重、乱序处理、心跳和重连。
6. 两年历史回填、限频、断点续传和 REST 补数。
7. UTC 聚合 5m、15m、1h、4h、1d K 线。
8. Ticker、标记价、指数价、持仓量 1m 快照与资金费率事件。
9. 缺口检测、质量报告、修复任务、Chunk 压缩和两年保留策略。

K 线唯一键固定为 `(venue,instrumentId,interval,openTime)`。

退出条件：修复后完整率不低于 99.99%，重复为零；中断后 30 秒内恢复；补数可重复执行且结果一致。

### A3 研究数据层

目标：把在线行情与新闻转成无未来函数、可冻结、可追溯的研究输入。

独立交付顺序：

1. 市场列表、自选、实时 K 线、成交量、行情新鲜度和缺口界面。
2. Parquet 分区写入，路径按交易所、市场、标的、周期、年月组织并使用 Zstd。
3. 不可变 Dataset Manifest、内容哈希、分区校验和、质量报告和引用保护。
4. BlockBeats Open API 与 CoinDesk RSS 适配器、许可登记和原始内容留存策略。
5. 外部 ID、规范 URL、内容指纹去重和 `publishedAt`、`ingestedAt`、`availableAt` 时间语义。
6. LLM 实体、币种、情绪、相关度、事件类型和置信度标注；模型、Prompt、Schema 和结果版本化。

退出条件：任一数据集可按 Manifest 重建并校验；新闻因子严格使用 `availableAt`，历史回测不存在未来函数。

### A4 策略与向量回测

目标：完成可编辑、可发布、可隔离执行的策略研发闭环和 vectorbt 回测。

独立交付顺序：

1. 策略包契约：`manifest.yaml`、入口 Python、可选模块和测试。
2. 草稿、不可变发布版本、参数 Schema、版本差异和引用保护。
3. Monaco 文件树、参数表单、诊断、差异、日志和草稿恢复。
4. 白名单 Worker 镜像和锁文件；禁止动态安装依赖和网络访问。
5. 默认资源限制：2 CPU、4GB、30 分钟、5GB 临时目录，支持取消和管理员调整。
6. vectorbt 1.1.0 适配，输出独立 LONG/SHORT `PositionTarget`。
7. 统一成交账本、权益曲线、费用、资金费率、指标和版本快照。
8. 黄金回测与完全可复现性测试。

退出条件：相同策略、数据集、参数和镜像生成相同交易账本；超时、资源超限和取消均能回收。

### A5 事件回测

目标：获得与真实订单语义接近的事件驱动回测，并可与向量结果对照。

独立交付顺序：

1. 标准 `OrderIntent`、订单状态、成交、仓位和账户账本契约。
2. NautilusTrader 1.230.0 数据适配与策略运行器。
3. 市价、限价、止损市价、止盈市价、GTC/IOC/FOK 和 `reduceOnly` 模型。
4. Bar 成交规则：收盘信号最早下一根开盘；跳空和同 Bar 止盈止损冲突采用不利结果。
5. 手续费、滑点、资金费率和逐仓双向仓模型。
6. 双引擎运行比较、结果解释和差异报告。
7. 回测详情：快照、质量、权益/回撤、月度收益、账本、费用、日志和多运行比较。

首版不模拟盘口排队和部分成交。

退出条件：黄金案例账本稳定；关键边界与手工计算一致；研究版本报告通过用户审查。

### A6 内置模拟盘

目标：使用实时行情验证订单、风控、账务和恢复，不依赖交易所 Demo/Testnet。

独立交付顺序：

1. 虚拟账户、余额、仓位、订单、成交和账本。
2. 实时 Bar/Ticker 撮合和统一订单状态机。
3. 幂等键、确定性 `clientOrderId`、未知状态与对账流程。
4. 完整订单前风控、行情新鲜度、时钟、连接、限频和对账门禁。
5. 急停、撤单并停止开仓、独立二次确认市价平仓。
6. 重启恢复、自动对账、告警和审计。
7. 交易驾驶舱、订单、仓位、风险、任务和移动监控界面。

默认限制：单笔不超过权益 2%，单标的多空毛敞口 10%，总毛敞口 30%，最高杠杆 2 倍；UTC 日亏 2% 或高水位回撤 5% 时禁止新增敞口，仅允许 `reduceOnly`。

退出条件：连续 30 天且至少 100 个订单，无未解释账务差异；任何重试不重复下单，急停后不新增敞口。

### A7 小额现货

目标：在用户手工放行后，以最小资金验证双所真实连接和恢复能力。

独立交付顺序：

1. 加密凭据元数据与 Executor 独占 Secret 注入边界。
2. Binance 现货私有 REST/WebSocket 连接器。
3. OKX 现货私有 REST/WebSocket 连接器。
4. 下单、撤单、成交回报、未知状态对账和限频恢复。
5. 启动与周期性余额、订单、成交和仓位对账。
6. 实盘总开关、账户放行、急停、审计和应急 Runbook。

退出条件：默认关闭；Testnet 连接器验证通过；用户手工注入密钥并放行；小额现货连续稳定 30 天后才可申请永续。

### A8 USDT 永续

目标：在现货稳定基础上增加逐仓双向持仓与合约特有风险控制。

独立交付顺序：

1. 合约品种、杠杆、保证金、标记价、资金费率和清算风险模型。
2. Binance USDT 永续私有连接器。
3. OKX USDT 永续私有连接器。
4. 逐仓双向仓、`reduceOnly` 和条件单状态机。
5. 保证金、强平距离、资金费率和仓位模式对账。
6. 永续专属风险限制、急停、告警和用户放行报告。

退出条件：模拟和 Testnet 的强平、资金费率、断连、重复回报、未知状态和重启恢复案例全部通过；用户手工放行。

## 5. API 与体验演进

- 默认首屏改为交易驾驶舱，展示行情新鲜度、数据缺口、账户净值、毛敞口、风控、任务、自选市场和告警。
- 导航调整为驾驶舱、市场、数据中心、新闻因子、策略、回测、交易、风险、自动化、系统。
- TradingView Lightweight Charts 用于实时 K 线、成交量和交易标记；ECharts 用于绩效与统计。
- 移动端只提供监控、告警、订单仓位、任务取消和急停；编辑器与工作流仅支持桌面端。
- 所有加载、空数据、部分失败、过期数据、取消中、重试中和只读状态必须有明确反馈。

## 6. CI、发布与供应链

目标门禁包括：

- Go：格式、Vet、Staticcheck、单元、竞态、集成和构建。
- Vue：ESLint、Stylelint、类型、单元、构建和关键 Playwright。
- Python：Ruff、Mypy、Pytest、锁文件和黄金回测。
- 数据库：空库升级、旧版本升级、回滚可行性和迁移幂等。
- 安全：Gitleaks、govulncheck、pip-audit 和 Trivy。
- 容器：Compose 启动、健康检查、API 冒烟和镜像扫描。

发布流水线从受保护的 `main` 构建带版本号和 Commit SHA 的镜像、SPDX JSON SBOM、校验和及发布说明，推送到生产主机私有 Registry，并在备份和 migration 成功后通过 DPanel Compose 自动更新。流水线只能由用户手工触发，使用专用 self-hosted Runner 和 `production` Environment；真实交易所密钥不进入 GitHub、Runner 日志或发布产物。

## 7. 总体验收门禁

- 修复后 K 线完整率不低于 99.99%，唯一键重复为零，连接中断后 30 秒内恢复。
- 回测任务取消在 5 秒内生效，Worker 崩溃后任务可安全回收。
- 相同策略、数据集、参数和镜像产生相同交易账本。
- 任何重试不得产生重复订单，急停后不得出现新增敞口。
- 重启后账户、订单、成交、仓位和余额自动对账。
- 模拟盘和小额现货分别满足 30 天观察期和对应报告门禁。
- 未通过 CI、用户代码审查或迁移/回滚说明的 PR 不得合并。

## 8. 时间与风险

质量优先估算：研究与双回测版本约 4 至 5 个月；完整模拟、现货和永续约 7 至 10 个月。模拟盘和现货观察期可与下一阶段关闭状态的开发并行，但不能提前放行。

主要风险与控制：

- 交易所协议和限频变化：连接器契约测试、录制脱敏样本、版本监控和降级开关。
- 数据缺口与未来函数：质量报告、`availableAt`、不可变数据集和黄金案例。
- 回测与实盘偏差：统一订单意图和账本，保守成交假设，双引擎对照。
- 重复订单和未知状态：稳定幂等键、确定性客户端订单号、先对账后重试。
- 家用主机故障：备份、就绪门禁、私网访问、固定镜像和演练过的回滚手册。
- AI 交付漂移：小 PR、仓库事实来源、自动门禁、独立只读复审和用户手工合并。
