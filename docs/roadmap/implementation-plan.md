# CoinSphere 全流程实施计划

本文件只保存稳定的产品边界、能力依赖、交付方式和验收门禁。动态进度以 GitHub 为准，架构细节以 ADR 和公共契约为准。

## 1. 交付与治理

- `main` 只接受用户手工合并的 PR；Codex 可以创建分支、提交、推送和草稿 PR，但禁止自动合并、生产放行或真实交易。
- 一个 Issue 和 PR 对应一个可使用、可验收和可回滚的纵向能力；A2.0-A2.4 等能力门只作父跟踪项。
- GitHub 保存当前进度和验收证据链接；仓库保存统一证据模板、指标口径、ADR、契约和 Runbook。
- Basic Memory 保存个人偏好、模型路由和本地环境入口，不复制项目事实、架构或动态状态。
- Migration 默认随能力交付；共享基线、破坏性或跨领域 schema、凭据、风控和订单状态机使用独立 PR。
- 项目为个人自用系统；在出现实测需求前不增加微服务、消息中间件、PgBouncer、对象存储、Kubernetes 或通用插件平台。

## 2. 目标架构

- Go 保持模块化单体和单镜像，目标角色模型为 `COINSPHERE_ROLE=api|collector|scheduler|executor`。
- A2.1 只实现并部署 `api`、`collector`、`scheduler`；`executor` 连同交易凭据能力从 A6 开始实现和部署。缺失或非法角色值必须拒绝启动。
- API 可多实例；Collector 按数据流租约分片；Scheduler 单活产生定时触发、多活认领任务和 Outbox；Executor 按交易账户独占租约并使用 fencing。
- PostgreSQL/TimescaleDB 是唯一在线数据库；任务队列、租约、Outbox 和跨 API 实例通知均复用 PostgreSQL。
- 普通角色与 Worker 首期共用受限应用身份，Executor 和 Migrator 独立；普通身份不得读取交易凭据。
- Backend、Worker、数据库会话和金融事件统一 UTC；用户计划单独保存 IANA 时区并显式计算触发时间。
- Python Worker Launcher 使用独立 Rootless Docker，直接认领 PostgreSQL 任务；任务容器无网络、DSN、密钥和 Docker Socket。

## 3. 能力计划

### A0 工程系统

结果：规则、ADR、契约、分层 CI、发布产物检查、手工部署与回滚入口可复现。

退出条件：适用检查可重复执行，发布产物不含凭据，用户手工合并和生产触发边界明确。

### A1 平台基线

结果：单一 PostgreSQL 基线、并发租约、Outbox、工作流事务、Auth/WebSocket 安全、内容安全和可观测性完成。

退出条件：空库可启动；核心安全、事务、恢复、生命周期和审计契约通过。

### A2 行情底座

- A2.0：冻结并实现 Decimal/UTC、Instrument/Candle/Ticker、最小 schema、MarketSource 和双所脱敏样本。
- A2.1：落地 Store、runner、多角色启动、数据库连接预算和 `market_candles` Timescale 生命周期。
- A2.2：实现 Binance/OKX 元数据、REST 历史、WebSocket 实时、断线补数与幂等写入。
- A2.3：以一个原子纵向 PR 完成 OpenAPI、后端、前端、测试和旧 `/api` 删除，不保留兼容层。
- A2.4：实现缺口检测、显式修复、跨周期质量事件、质量报告和品种启用管理。

首期全量同步品种元数据，只采集启用集；默认启用两所 BTC/ETH 的 USDT 现货和永续。保存交易所原生 `1m/5m/15m/1h/4h/1d`，日线使用 UTC 边界。各周期以同周期 REST 修复结果为权威，1m 聚合只做交叉检查。

退出条件：每条 `venue+instrument+interval` 启用流在滚动 30 天已闭合可交易时间槽内完整率不低于 99.99%，重复键为零；本地确认断线至首条规范化事件落库不超过 30 秒；补数可重复执行且结果一致。

### A3 研究输入

- A3-core：策略草稿、不可变发布版本、引用保护、可复现 Parquet 数据集、Manifest 和质量报告。
- A3-news：在 A4 后增加原始新闻采集和版本化 LLM 因子，严格使用 `availableAt`，不阻塞核心量化闭环。

产物先放本机内容寻址不可变卷。Manifest 在哈希校验后原子登记；失败保留源数据并重试。已发布策略、引用数据集和交易证据禁止自动删除；临时失败文件保留 7 天，未引用普通回测报告保留 90 天。

### A4 策略与向量回测

结果：固定 digest 白名单镜像、无网络一次性任务容器、Monaco 多文件策略、vectorbt 和统一结果 Manifest。

最小交易语义包含市价、限价和止损。信号基于闭合 Bar；同 Bar 冲突按保守固定路径、止损优先和创建顺序处理，不模拟盘口排队或部分成交。跳空止损按不利开盘价，限价可获得更优开盘价。

退出条件：相同策略、数据集、参数和镜像产生相同规范化订单、成交和结果；取消 5 秒内生效，超时与资源超限均回收容器。

### A5 账本语义验证

Go 使用追加式复式分录作为权威账本，余额和仓位是可重建投影，纠错只追加冲正或调整。Python 输出非权威回测事实，Go 校验后生成账本。

A5 必须完成订单、成交、费用、仓位和分录黄金案例。权威账本任一可复现逐项差异触发 NautilusTrader；Nautilus 只固化差异案例，不让普通回测永久双跑。

### A6 R1 模拟盘

实现并部署 `executor`，建立 `paper/live` 交易 realm、交易权限状态机、虚拟账户、撮合、风控、恢复和对账。Realm 只覆盖账户、凭据、权限、Intent、订单、成交、仓位、余额、账本和风控状态，行情、数据集和策略保持公共。

账户硬上限必须全部显式配置，策略只能更严格。缺少任一限制时交易保持禁用。R1 通过 A5 后由用户手工放行。

### A7 R2 小额现货

模拟盘至少运行 30 天并完成 100 笔订单，且账务、恢复和急停证据通过后，才可申请小额现货。进入 R2 前必须完成：

- 构建与生产固定部署器权限分离，生产部署只接受已校验 digest/Manifest。
- 策略包、审批证据、Manifest、账务和对账报告的加密独立副本及恢复演练。
- Web 凭据录入使用 Executor 公钥信封加密；新凭据验证后原子启用，旧版本只用于在途对账后撤销。

### A8 R3 USDT 永续

小额现货稳定至少 30 天后，另完成永续模拟/Testnet 至少 30 天和 100 笔订单，并覆盖强平、资金费率、断连、重复回报、未知状态和重启恢复，才可申请用户手工放行。

## 4. API 与数据契约

- OpenAPI 3.0.3 是 `/api/v1` 单一来源；生成 Go/TypeScript 类型随契约提交，CI 重新生成并检查漂移，`oasdiff` 检查破坏性变更。
- 错误使用 `application/problem+json`；列表使用默认 50、最大 200 的不透明游标，并以唯一 ID 保证稳定排序。
- 普通异步任务的 `Idempotency-Key` 保留 24 小时；交易命令的键、请求摘要、账户和订单与审计记录同寿命，同键不同载荷返回冲突。
- 通知记录先持久化，PostgreSQL `NOTIFY` 只作唤醒；每个 API 实例查询后推送自己持有的连接，离线用户重连后以未读快照恢复。

## 5. Migration 与验证

- A2-A5 尚未进入正式观察期，可重置开发数据并整理历史 migration；A6/R1 开始前冻结全部历史文件，此后只能追加。
- Timescale 目标为 7 天 chunk、30 天后压缩、默认在线保留 2 年。压缩失败保留未压缩数据并告警；retention 独立执行，删除失败不影响采集。
- 在线保留期到期后只保护已发布且被引用的数据集，不建设全量 K 线冷归档。
- PR 运行受影响模块快速检查；波次运行一次跨模块完整门禁；`main`、定时和发布承担完整供应链检查。
- 门禁模板保存在仓库，具体 CI、Manifest、哈希、演练和用户审批链接保存在 GitHub。
