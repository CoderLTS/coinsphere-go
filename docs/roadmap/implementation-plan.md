# CoinSphere AI 全流程实施计划

- 状态：已接受，执行中
- 更新日期：2026-08-03
- 交付方式：所有实现和修改使用当前主模型；`gpt-5.6-terra`（思考等级 `max`）只用于资料检索、仓库探索、代码阅读和信息整理
- 产品负责人和最终放行人：用户

## 1. 交付与治理

项目由 Codex 完成需求细化、架构设计、实现、必要验证、文档、排障和发布产物制作。用户负责产品方向、高风险取舍、PR 审查、GitHub 与家用 Linux 配置、生产凭据注入、手工合并和阶段放行。

必须遵守以下边界：

- Codex、GitHub 和 CI 永不接触真实交易所密钥或发起真实订单；允许用户手工触发受 `production` Environment 约束的发布工作流连接生产主机并自动部署。
- `main` 只接受用户手工合并的 PR，禁止直接提交和自动合并；当前私有仓库套餐无法强制分支保护时，以仓库操作规则约束，升级套餐后再启用平台强制规则。
- 分支使用 `codex/<issue-id>-<slug>`；每个 PR 交付一个可直接使用、可独立验收和回滚的纵向能力，不为单个校验、门禁或内部步骤拆 PR。
- 数据库迁移、凭据、风控和订单状态机使用独立 PR，并提供回滚说明。
- 每个 PR 只保留与本次行为相关的目标、接口或迁移影响、验证结果、风险和回滚；没有界面变化时不制作界面证据。
- 同一开发波次集中完成实现，只在波次或 PR 完成后执行一次适用验证和一次只读复审，不在子步骤之间反复插入审核。
- 需求、ADR、API 契约、测试和代码是事实来源，聊天上下文不能成为唯一设计依据。
- Renovate 每周创建依赖 PR，所有依赖更新均由用户审查并手工合并。

### 1.1 开发取舍

- 仅在 API、外部数据、URL、文件、凭据、金融状态和数据库约束等信任边界校验；内部函数依赖已经验证的类型和状态，不重复判空、兜底或断言。
- 项目按全新系统开发，允许重置未投产的开发数据；不增加旧 schema、旧数据、旧接口或多数据库兼容层。
- 新增或修改的非平凡代码使用准确的中文注释或 Docstring，说明设计目的、状态转换、并发/事务边界和失败语义；禁止逐行教学式注释。
- 新增运行流程使用结构化日志覆盖启动、停止、关键状态、外部调用、重试、取消、失败和终态；日志只记录资源 ID、Worker ID、状态、耗时和错误分类，不记录凭据、令牌、原始载荷或个人数据。
- 数据采集、工作流和通知只抽取当前已有两个以上实现真正共享的契约，不建设插件平台、微服务或未来扩展框架。

### 1.2 Agent 并行规则

- 只有两个以上子任务的公共契约已冻结、文件所有权独立且并行能缩短关键路径时才创建子 Agent；串行依赖、共享核心文件或短任务由根 Agent 直接完成。
- 所有代码实现、修改、架构决策、安全审查、共享核心和最终只读复审均使用当前主模型；`gpt-5.6-terra`、思考等级 `max` 只用于资料检索、仓库探索、代码阅读、文件定位和信息整理，不承担实现。
- 并行 PR 使用独立 Git worktree。子 Agent 不修改其他 worktree、共享计划文档或集成分支；根 Agent 负责冻结契约、解决冲突、rebase、集中验证和汇总报告。

### 1.3 验证投入

- 核心自动化测试只覆盖金融 Decimal/UTC、数据库约束与 migration、并发事务、SSRF/Auth、采集去重补数、订单状态机、风控、账务和对账。
- CRUD、DTO 映射、简单配置、日志包装、普通 UI 和工作流/通知胶水不新增单元测试，只执行编译、类型检查、Lint 或一次人工冒烟。
- PR 只运行受影响模块的构建和核心测试；PostgreSQL Compose、关键浏览器和跨模块集成每个开发波次集中运行一次；完整供应链扫描只在 `main`、定时任务或发布时运行。

## 2. 产品范围

### 2.1 核心范围

- Binance 与 OKX 双交易所。
- 现货、USDT 永续逐仓双向持仓。
- 内置模拟盘；实盘按模拟盘、小额现货、USDT 永续顺序放行。
- vectorbt 1.1.0 向量回测与 NautilusTrader 1.230.0 事件回测。
- Monaco 多文件 Python 策略编辑器。
- PostgreSQL/TimescaleDB 在线数据和不可变 Parquet 数据集。
- 中英双语新闻与版本化 LLM 情绪、相关度和事件因子。
- 保留 RBAC、AI 助手、通知和工作流，不建设 SaaS 多租户、计费或开放注册。

### 2.2 首轮非目标

- 逐笔成交、完整盘口和高频交易。
- 跨交易所套利和多标的组合优化。
- 币本位、全仓、复杂清算模拟。
- OCO、TWAP 等高级算法单。
- AI 自主交易或绕过风控的自动执行。

## 3. 目标架构

### 3.1 运行边界

- Go 保持模块化单体，领域模块为 `marketdata`、`dataset`、`news`、`strategy`、`backtest`、`trading`、`risk`、`workflow`、`platform`。
- 同一 Go 代码库构建 `api`、`collector`、`executor`、`scheduler` 四种进程。
- Python 3.12 Worker 独立容器运行数据集生成、vectorbt 与 NautilusTrader。
- PostgreSQL/TimescaleDB 是唯一数据库运行栈；Backend、Worker 和 migration 共用同一实例与明确 schema，不保留 SQLite/MySQL 驱动、方言 SQL 或数据迁移路径。
- PostgreSQL `FOR UPDATE SKIP LOCKED` 实现任务队列，事务 Outbox 实现可靠事件；首版不引入 Redis、Kafka 或 NATS。
- TimescaleDB 保存在线行情和业务状态，共享卷保存 Parquet、策略包、日志与回测产物。
- Binance 使用官方 Go Connector；OKX 使用官方 REST/WebSocket 协议的薄适配器。
- 工作流只编排补数、数据集、批量回测、报告和通知，不参与逐 K 线计算或下单。
- 家用 Linux 使用 Docker Compose `research`、`paper`、`live` Profile，只允许 LAN 或 Tailscale/WireGuard 私网访问。

### 3.2 不可破坏的契约

- 时间统一使用 UTC `timestamptz` 和 RFC3339Nano。
- 价格、金额、数量和费率使用 Decimal 与 `numeric(38,18)`，禁止账务使用 `float64`，JSON 使用字符串。
- 新金融 API 位于 `/api/v1`，金融 ID 使用 UUIDv7，列表使用游标分页。
- 命令接受 `Idempotency-Key`；错误使用 `application/problem+json`。
- WebSocket 信封固定为 `{type,version,sequence,occurredAt,data}`。
- 策略为“可编辑草稿 + 不可变发布版本”，回测、模拟和实盘只能引用发布版本。
- 数据集包含不可变 Manifest、内容哈希、分区校验和、质量报告和来源修订号；被引用后禁止覆盖。
- 模拟与实盘账户、凭据、订单、仓位和风控状态强逻辑隔离。

### 3.3 通用能力边界

- 数据采集统一为 `MarketSource` 的元数据、历史分页和实时订阅能力，输出规范化的 Instrument、Candle 和 Ticker；交易所实现只负责协议映射，共享 runner 负责生命周期、限频、断点、日志和存储。
- 工作流继续复用现有引擎，通过任务类型、参数 Schema 和资源 ID 调用领域能力，不把交易所协议、逐 K 线计算或下单逻辑写入节点。
- 通知统一接收领域事件和 `NotificationMessage`，渠道实现只负责发送；业务模块不直接调用具体通知渠道。
- 不为尚未出现的第三种交易所、任务系统或通知协议引入动态插件加载、兼容适配层或独立服务。

## 4. 分阶段实施

### A0 工程系统

目标：建立所有后续金融代码必须经过的工程治理和可重复验证入口。

独立交付顺序：

1. 规则、路线图、架构总览、ADR、契约、PR/Issue 模板、本地验证脚本与 Go/Vue/Python 基础 CI。
2. 清理现有前端 Stylelint 基线，将 Stylelint 设为阻塞检查。
3. 已建立版本化 SQL migration 工具；历史双方言与存量升级骨架只作为过渡实现，A1 PostgreSQL 基线 PR 会删除并以全新空库基线取代。
4. 建立关键 Playwright 冒烟、Worker 容器、Compose 健康测试和 API 冒烟。
5. 已建立 Gitleaks、govulncheck、pip-audit、Trivy 镜像扫描、SBOM、校验和、最终发布产物安全与完整性扫描，以及生产主机私有 Registry 发布流水线。
6. 用户配置远程仓库、分支保护、Actions 权限和 Renovate App。

当前进度：A0 已完成并经用户手工放行。Python Worker、Compose/CI 健康检查、关键浏览器冒烟和发布产物扫描均已建立；A1 起按分级验证策略运行，不再让完整浏览器、容器和供应链矩阵阻塞每个普通 PR。

退出条件：适用的 A0 检查可在干净 checkout 复现，当前 GitHub 套餐下的 PR/手工合并约束已记录，发布产物不包含凭据，回滚手册经过桌面演练。

### A1 基础稳定化

目标：先消除现有通用平台中会放大金融风险的并发、认证和安全缺陷。

已交付基础：

1. A1-1 至 A1-4 已合并：全链路取消、Worker 租约与取消、事务 Outbox、工作流版本与激活事务闭环均已建立。
2. A1-5 通知 WebSocket 的单 writer、有限队列、RFC6455 心跳、连续序号、固定信封、同源代理和慢连接摘除已完成实现与集中验证，状态为“待用户审查合并”，不得提前记为已合并。

A1-5 收口只执行一次 WebSocket 并发/安全核心测试、后端构建、前端类型与生产构建，以及一次只读复审；不在本 PR 扩展 Token、数据库或观测能力。

剩余目标合并为三个纵向 PR，可在独立 worktree 中并行实现：

| 分支 | 纵向交付 | 主要接口变化 | 合并顺序 |
| --- | --- | --- | ---: |
| `codex/a1-postgres-baseline` | 将当前模型压成新的 PostgreSQL 基线 migration；删除 SQLite/MySQL 驱动、双方言 SQL、AutoMigrate、旧数据升级验证和 SQLite 部署卷；Backend、Worker 共用 TimescaleDB，开发数据直接重置 | 数据库配置只保留 PostgreSQL DSN 和连接池参数 | 1 |
| `codex/a1-security-baseline` | HTTP 节点精确域名 allowlist、公共地址校验、重定向复检和敏感 Header 过滤；Access Token 仅存内存，Refresh Token 使用轮换 HttpOnly Cookie；关闭注册/找回密码并提供管理员 CLI；Mermaid strict、内容清洗和 CSP | 登录只返回 Access Token；refresh/logout 使用 Cookie；通知 WebSocket 使用固定 `Sec-WebSocket-Protocol`，删除查询串 Token | 2 |
| `codex/a1-observability` | 使用 `log/slog` 输出 JSON 日志；生成请求 ID；提供持久化审计事件、有限低基数 Prometheus 指标、存活和数据库就绪检查；补齐工作流、Outbox、Worker、WebSocket 和通知关键日志 | `/health/live`、`/health/ready`、`/metrics`；删除单一 `/health` | 3 |

退出条件：PostgreSQL 空库可通过单一基线启动；SSRF、Auth 轮换、WebSocket 鉴权和 Mermaid/XSS 信任边界有核心自动化检查；结构化日志、审计、指标、存活和就绪接口可用；A1 并发与事务契约无回归。

### A2 行情底座

目标：获得可持续运行、可修复并可量化质量的双所行情事实源。

依赖与并行波次：

1. 先由根 Agent 冻结 TimescaleDB schema、Decimal/UTC 类型、Instrument/Candle/Ticker 规范化结构、`MarketSource` 接口、存储写入和 `/api/v1` 契约；该公共契约单独合并，后续切片不得各自发明类型。
2. 契约合并后并行开发 Binance 纵向切片：全量品种、1m 实时、两年历史分页、限频和断点恢复。
3. 同时并行开发 OKX 纵向切片，输出与 Binance 完全相同的规范化结构，不把交易所字段泄漏到公共存储和 API。
4. 同时并行开发公共数据能力与界面：批量幂等写入、缺口检测/修复、UTC 聚合、Ticker/衍生品快照、质量报告、保留策略、市场列表与新鲜度界面。
5. 三个切片集成后再完成 BTC/ETH 固定选择和双所共同品种的成交额推荐；只在波次末运行一次 PostgreSQL/TimescaleDB、双所样本和界面冒烟。

K 线唯一键固定为 `(venue,instrumentId,interval,openTime)`。

退出条件：修复后完整率不低于 99.99%，重复为零；中断后 30 秒内恢复；补数可重复执行且结果一致。

### A3 研究数据层

目标：把在线行情与新闻转成无未来函数、可冻结、可追溯的研究输入。

依赖与并行波次：

1. 先冻结 Dataset Manifest、Parquet 分区、内容哈希、引用保护，以及新闻 `publishedAt`、`ingestedAt`、`availableAt` 和 LLM 结果版本契约。
2. 并行开发数据集纵向切片：按交易所、市场、标的、周期和年月写入 Zstd Parquet，生成不可变 Manifest、校验和与质量报告。
3. 并行开发新闻纵向切片：用共享 `NewsSource` 契约实现 BlockBeats Open API 与 CoinDesk RSS，完成许可登记、外部 ID/URL/内容指纹去重和原始内容策略。
4. 并行开发研究体验与自动化切片：自选、实时 K 线、成交量、缺口界面，LLM 实体/币种/情绪/相关度/事件标注，以及通过资源 ID 触发的数据集、新闻和通知工作流。

退出条件：任一数据集可按 Manifest 重建并校验；新闻因子严格使用 `availableAt`，历史回测不存在未来函数。

### A4 策略与向量回测

目标：完成可编辑、可发布、可隔离执行的策略研发闭环和 vectorbt 回测。

依赖与并行波次：

1. 先冻结策略包 `manifest.yaml`、入口 Python、参数 Schema、不可变发布版本、`PositionTarget` 和统一成交账本契约。
2. 并行开发策略管理与 Monaco 纵向切片：草稿、发布、版本差异、引用保护、文件树、参数表单、诊断、日志和草稿恢复。
3. 并行开发 Worker 沙箱与 vectorbt 纵向切片：白名单镜像和锁文件、无网络执行、2 CPU/4GB/30 分钟/5GB 默认限制、取消和独立 LONG/SHORT 输出。
4. 并行开发回测结果纵向切片：统一账本、权益、费用、资金费率、指标和版本快照；波次末只为确定性账本和资源回收保留黄金测试。

退出条件：相同策略、数据集、参数和镜像生成相同交易账本；超时、资源超限和取消均能回收。

### A5 事件回测

目标：获得与真实订单语义接近的事件驱动回测，并可与向量结果对照。

依赖与并行波次：

1. 先冻结 `OrderIntent`、订单状态、成交、仓位、账户账本和费用模型；A4/A5 共用该契约，不为两个引擎复制模型。
2. 并行开发 NautilusTrader 纵向切片：数据适配、策略运行器、市价/限价/止盈止损、GTC/IOC/FOK、`reduceOnly`、逐仓双向仓、手续费、滑点和资金费率。
3. 并行开发保守 Bar 成交与黄金案例：收盘信号最早下一根开盘，跳空和同 Bar 止盈止损冲突采用不利结果；不模拟盘口排队和部分成交。
4. 并行开发双引擎比较与回测详情：快照、质量、权益/回撤、月度收益、账本、费用、日志、差异解释和多运行比较。

首版不模拟盘口排队和部分成交。

退出条件：黄金案例账本稳定；关键边界与手工计算一致；研究版本报告通过用户审查。

### A6 内置模拟盘

目标：使用实时行情验证订单、风控、账务和恢复，不依赖交易所 Demo/Testnet。

依赖与并行波次：

1. 先冻结虚拟账户、余额、仓位、订单、成交、账本、订单状态机、幂等键和订单前风控契约；该核心由根 Agent 处理并单独合并。
2. 并行开发模拟撮合纵向切片：实时 Bar/Ticker 撮合、确定性 `clientOrderId`、未知状态和重试语义。
3. 并行开发恢复与风险纵向切片：重启恢复、自动对账、行情新鲜度、时钟/连接/限频检查、急停、撤单停止开仓和二次确认平仓。
4. 并行开发交易驾驶舱与通知纵向切片：账户净值、订单、仓位、风险、任务、移动监控、告警和审计。

默认限制：单笔不超过权益 2%，单标的多空毛敞口 10%，总毛敞口 30%，最高杠杆 2 倍；UTC 日亏 2% 或高水位回撤 5% 时禁止新增敞口，仅允许 `reduceOnly`。

退出条件：连续 30 天且至少 100 个订单，无未解释账务差异；任何重试不重复下单，急停后不新增敞口。

### A7 小额现货

目标：在用户手工放行后，以最小资金验证双所真实连接和恢复能力。

依赖与并行波次：

1. 先冻结凭据元数据、Executor 独占 Secret、实盘总开关、账户放行、订单路由和风险边界；新交易能力保持默认关闭。
2. 并行开发 Binance 现货纵向切片：私有 REST/WebSocket、下单、撤单、成交回报、限频和未知状态恢复。
3. 并行开发 OKX 现货纵向切片，复用相同订单、成交和对账契约。
4. 并行开发公共对账与控制纵向切片：启动/周期余额、订单、成交、仓位对账，急停、审计、监控和应急 Runbook。

退出条件：默认关闭；Testnet 连接器验证通过；用户手工注入密钥并放行；小额现货连续稳定 30 天后才可申请永续。

### A8 USDT 永续

目标：在现货稳定基础上增加逐仓双向持仓与合约特有风险控制。

依赖与并行波次：

1. 先冻结合约品种、杠杆、保证金、标记价、资金费率、清算风险、逐仓双向仓、`reduceOnly` 和条件单状态机。
2. 并行开发 Binance USDT 永续纵向切片，复用 A7 凭据、订单、回报和恢复基础。
3. 并行开发 OKX USDT 永续纵向切片，输出相同的规范化仓位和风险状态。
4. 并行开发公共风险与监控纵向切片：保证金、强平距离、资金费率、仓位模式对账、永续专属限制、急停、告警和用户放行报告。

退出条件：模拟和 Testnet 的强平、资金费率、断连、重复回报、未知状态和重启恢复案例全部通过；用户手工放行。

## 5. API 与体验演进

- 默认首屏改为交易驾驶舱，展示行情新鲜度、数据缺口、账户净值、毛敞口、风控、任务、自选市场和告警。
- 导航调整为驾驶舱、市场、数据中心、新闻因子、策略、回测、交易、风险、自动化、系统。
- TradingView Lightweight Charts 用于实时 K 线、成交量和交易标记；ECharts 用于绩效与统计。
- 移动端只提供监控、告警、订单仓位、任务取消和急停；编辑器与工作流仅支持桌面端。
- 所有加载、空数据、部分失败、过期数据、取消中、重试中和只读状态必须有明确反馈。

## 6. CI、发布与供应链

验证分为三层，不把所有检查放进每个 PR：

1. PR 快速层：只对受影响模块执行格式/Lint、Go 或 Python 编译、Vue 类型与生产构建，以及本 PR 涉及的核心测试。非核心 CRUD、映射、配置、日志包装、普通 UI 和工作流/通知胶水不新增单元测试。
2. 波次集成层：每个开发波次结束后集中运行一次 PostgreSQL/TimescaleDB migration、Compose 健康、跨模块 API、关键浏览器路径和必要竞态检查；子 PR 开发过程中不重复运行完整矩阵。
3. `main`/定时/发布层：运行 Gitleaks、govulncheck、pip-audit、Trivy、镜像/SBOM/校验和/Manifest/危险路径与敏感内容扫描，以及最终容器和发布产物验证。

数据库只验证 PostgreSQL 空库 Up、当前版本启动和本次 migration 的必要回滚。A1 基线允许压缩尚未投产的历史 SQL；基线建立后，每次结构变更必须追加新的版本化 SQL，不修改已应用历史文件，也不为旧数据或其他数据库补兼容路径。

发布流水线从受保护的 `main` 构建带版本号和 Commit SHA 的镜像、SPDX JSON SBOM、校验和及发布说明；最终产物扫描通过后才允许上传 GitHub Artifact 和部署，并在备份和 migration 成功后通过 DPanel Compose 自动更新。镜像推送到生产主机私有 Registry。流水线只能由用户手工触发，使用专用 self-hosted Runner 和 `production` Environment；真实交易所密钥不进入 GitHub、Runner 日志或发布产物。

## 7. 总体验收门禁

- 修复后 K 线完整率不低于 99.99%，唯一键重复为零，连接中断后 30 秒内恢复。
- 回测任务取消在 5 秒内生效，Worker 崩溃后任务可安全回收。
- 相同策略、数据集、参数和镜像产生相同交易账本。
- 任何重试不得产生重复订单，急停后不得出现新增敞口。
- 重启后账户、订单、成交、仓位和余额自动对账。
- 模拟盘和小额现货分别满足 30 天观察期和对应报告门禁。
- 未通过本 PR 适用的快速验证、用户代码审查或必要迁移/回滚说明的 PR 不得合并；非适用的完整门禁不得阻塞普通开发 PR。

## 8. 时间与风险

原串行估算为研究与双回测 4 至 5 个月、完整模拟/现货/永续 7 至 10 个月。改为依赖波次和纵向并行后，不再把该数字作为逐项工期承诺；每个阶段在公共契约合并后根据三个并行切片的实际吞吐重新估算。模拟盘和现货观察期可与下一阶段“默认关闭”的开发并行，但不得缩短或提前放行。

主要风险与控制：

- 交易所协议和限频变化：连接器契约测试、录制脱敏样本、版本监控和降级开关。
- 数据缺口与未来函数：质量报告、`availableAt`、不可变数据集和黄金案例。
- 回测与实盘偏差：统一订单意图和账本，保守成交假设，双引擎对照。
- 重复订单和未知状态：稳定幂等键、确定性客户端订单号、先对账后重试。
- 家用主机故障：备份、就绪门禁、私网访问、固定镜像和演练过的回滚手册。
- AI 交付漂移：最小公共契约、纵向 PR、独立 worktree、波次末一次验证与复审，以及用户手工合并；没有并行收益时不创建子 Agent。
