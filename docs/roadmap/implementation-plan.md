# CoinSphere 自用优先实施计划

本文只保存稳定产品边界、纵向交付顺序和退出条件。动态进度、验收链接和用户放行记录只保存在 GitHub。

## 交付原则

- 一个 Issue 和 PR 交付一个可直接使用、独立验收和回滚的纵向能力；不再建立父跟踪 Issue。
- Ready PR 必须以 `main` 为 base，用户审查并手工合并；禁止自动合并、自动生产发布和自动真实交易。
- 新金融能力使用 PostgreSQL/TimescaleDB、UTC、Decimal 和 `/api/v1`，不增加旧接口、旧数据或多数据库兼容层。
- Go App、Python Worker 和 Go Executor 均按单实例设计。任务队列、Outbox 和崩溃恢复复用 PostgreSQL，不增加中间件。
- 工作流保持通用能力，但只能消费量化事件并做粗粒度编排；交易私有协议、逐 K 线计算、风控和下单不进入工作流。
- 每个交易阶段默认关闭。通过自动化检查只证明软件满足进入人工审查的条件，不自动授予下一阶段权限。

## M1 研究闭环

### 1. 治理与契约重置

更新架构、路线图、公共契约、质量门禁和 GitHub 治理；新增 ADR-0008 至 ADR-0011，并标记被替代的旧 ADR。关闭旧 A2-A8 跟踪项，建立 M1-M4 和本计划对应的纵向 Issue。

退出条件：文档链接、术语、ADR 状态和 GitHub 跟踪关系一致；PR 不包含业务代码、migration 或依赖变化。

### 2. 原子 `/api/v1`、登录边界与资源隔离

先盘点全部旧 HTTP/WebSocket、Auth Cookie 和前端调用，再在一个纵向 PR 中同步迁移 OpenAPI、Go、TypeScript、前端和测试。删除旧 `/api`，不保留重定向或兼容层；关闭公开注册并移除注册 UI，除登录页外所有业务页面要求登录。

管理员可创建用户和发布策略；共享资源与所有者资源按公共契约分离。现有后台壳、RBAC 和工作流 UI 保留，演示页面和未使用资源只在本 PR 触及的导航路径内删除。

退出条件：运行时代码、前端、测试和生成契约均不再引用旧 `/api`；跨用户读写测试全部拒绝；登录、登出和五分钟复验闭环通过。

### 3. Binance Spot 与 USD-M 行情

移除 OKX 公共契约和未使用实现，删除 `market_flow_leases` 与单流 Runner。Go App 同步 Binance 全部 Spot/USD-M 品种元数据，按回测请求补齐历史，只订阅自选和已启用策略使用的原生周期，最低 `1m`。

WebSocket 与 REST 进入同一规范化和幂等写入路径。只由闭合 K 线触发策略任务；已闭合记录默认冻结，显式修复必须记录原因。Timescale 使用 7 天 chunk、30 天后压缩和默认两年 retention。

退出条件：官方脱敏载荷、重复写入、断线补数、按需回填、闭合判断和 retention 集成检查通过；本地连接失效到恢复落库目标不超过 30 秒。

### 4. 单文件策略与确定性回测

增加管理员单文件代码编辑、草稿、校验和不可变发布版本；策略版本固定市场、品种、周期、回看窗口、简单参数 Schema 和 Worker 运行时。普通用户只能查看已发布版本并创建私有策略实例或回测。

Worker 队列增加 `realtime/backtest` 通道，实时保留一个执行槽，回测使用一个受限子进程槽。V1 实现窄范围 Decimal Bar 模拟器，不引入 vectorbt、NautilusTrader、逐任务 Docker、多文件包或运行时依赖安装。

回测逐根调用与实时相同的 `on_bar`，在下一根开盘按目标仓位差成交；Spot 覆盖费用和滑点，USD-M 另覆盖资金费、逐仓单向仓、固定杠杆和保守强平。同 Bar 歧义采用更不利路径。

退出条件：无未来数据、下一根开盘成交、费用、滑点、资金费、止损、强平和取消黄金案例通过；相同输入产生相同结果与 SHA-256；耗时回测不能占用实时槽。

## M2 信号闭环

### 5. 实时信号、通知与人工批准

闭合 K 线落库后投递实时任务，Worker 输出归一化目标仓位，Go App 校验并持久化信号。增加 `signal_only | manual | auto`、手动信号下一根闭合时过期、管理员自动化授权和用户启用开关。

扩展现有通知模块，静态支持站内、钉钉、官方 QQ Bot 和 SMTP。关键交易事件按固定规则投递，普通事件继续通过工作流；外部按钮只打开一次性短期站内链接，批准仍要求登录、五分钟复验和 `Idempotency-Key`。

移动端首轮只覆盖批准/拒绝、持仓、订单、风险状态和全局急停。

退出条件：正常负载下闭合事件到信号持久化 p99 不超过两秒；重复事件不生成重复信号；过期、越权、重复批准和 Bot 回调下单全部被拒绝；渠道限流、重试和脱敏检查通过。

### 6. Paper Executor、风险与事件投影

部署单实例 Go Executor，先只启用 Paper。每个账户显式配置品种白名单、账户总名义金额、单品种金额、单笔金额、日亏损、最大回撤和报价最大年龄；USD-M 另固定低杠杆、逐仓和单向仓。缺少任一适用上限时禁止自动化。

同一 `account + market + symbol` 只允许一个 manual/auto 策略拥有活动仓位。Executor 按目标仓位差生成市价命令；全局急停或风险暂停后禁止增仓，只允许减仓、平仓和撤单。

只追加订单、成交、手续费和资金费事件，仓位、余额和盈亏由事件重建；不建设复式总账。

退出条件：重复命令、进程重启、暂停、急停和投影全量重建检查通过，且不存在未解释差异；用户手工批准后才进入 M3。

## M3 Testnet 闭环

### 7. Binance Spot 与 USD-M Testnet

用户经 HTTPS 录入凭据，Go App 使用现有对称主密钥加密且永不回显；保存前必须确认关闭提现和配置 IP 白名单，不自动验证权限。Executor 是唯一读取凭据并调用私有接口的组件。

Spot 使用市价差额单和随成交重建的数量型保护止损。USD-M 固定逐仓、单向和低杠杆，保护单使用 `STOP_MARKET + closePosition=true + workingType=MARK_PRICE`。任何保护单无法确认时，立即市价平仓并暂停策略。

退出条件：Spot 和 USD-M 分别通过确定性 `clientOrderId`、未知订单查询、断线恢复、重复回报、对账、保护单失败和平仓急停演练；无未解释差异后由用户手工放行 Spot 实盘。

## M4 小额实盘

### 8. Spot 手动批准与小额自动

先开放 Spot Live manual，每笔信号由用户复验后批准。手动路径的恢复、对账和保护止损证据稳定后，管理员授权且用户显式启用的小额 Spot auto 才可运行。

退出条件：交易额度保持在用户配置的硬上限内，所有订单、成交、费用和保护单均可对账；急停演练通过且用户手工批准进入 USD-M 实盘。

### 9. USD-M 手动批准与小额自动

先开放 USD-M Live manual，再开放小额 auto。执行始终固定逐仓、单向和低杠杆；资金费、强平距离、保护单、未知状态和重启恢复均纳入对账。

退出条件：适用证据无未解释差异，用户分别手工批准 manual 和 auto。代码、部署或历史阶段通过均不能自动启用该能力。

## API、数据与 Migration

- OpenAPI 3.0.3 是 `/api/v1` 唯一来源；生成 Go/TypeScript 类型随契约提交并检查漂移。错误使用 `application/problem+json`，列表默认 50、最大 200，使用稳定不透明游标。
- 新金融资源使用 UUIDv7；时间使用 UTC `timestamptz`/RFC3339Nano，价格、数量、金额、费率和目标仓位使用 Decimal，JSON 输出十进制字符串。
- 普通异步命令的 `Idempotency-Key` 保留 24 小时；交易命令键和请求摘要与订单审计同寿命。同键不同载荷返回冲突。
- 正式 Paper 观察前允许重整历史 migration 并重置未投产开发/CI 数据；开始记录 Paper 晋级证据前完成最后一次空库重放并永久冻结，此后只追加 migration。
- 普通 K 线默认在线保留两年；晋级候选使用本机内容寻址 `JSONL.gz` 和 SHA-256 冻结完整输入与结果，不建设全量冷归档。

## 验证与证据

- 每个 PR 执行受影响模块的快速检查；每个里程碑组合后只执行一次跨模块完整门禁和一次根 Agent 最终只读复审。
- GitHub Issue 链接 CI run、数据/结果 Manifest、质量报告、恢复或急停演练和用户审批。仓库只保存稳定模板与指标口径。
- 晋级使用证据清单和用户手工放行，不使用固定运行天数或订单数代替正确性证据。
- 真实交易密钥不得进入仓库、日志、测试、Issue、PR、CI 或 AI 上下文；生产部署和真实交易均只能由用户手工触发。
