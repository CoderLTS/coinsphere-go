# ADR 0006：Graph v3 多入口与插件 Profile 所有权

## 状态

已接受，适用于重新初始化后的业务数据库。

## 决策

CoinSphere 继续以工作流作为唯一编排核心，但工作流修订采用 Graph v3：图只保存节点、端口连线、类型化输入绑定和已发布 Profile 引用。入口节点可以有任意数量；每个入口独立创建 Run，并从自己的入口节点计算可达子图。共享节点只在同一个 Run 内汇聚，不能跨 Run 等待或复用输出。

工作流修订固定 `pluginId/profileId/version/type`。Profile 的 Schema、页面、权限、凭据、数据存储、版本和运行时解析均由插件拥有；Core 只负责引用校验、修订固化和 Run 快照。停用 Profile 不能被新修订引用，但已经固定该版本的修订仍可解析和运行。

边只表达源端口到目标端口的拓扑关系。普通输入只允许 `node`、`event`、`profile` 和 `literal` 绑定。条件、状态变化、去重、节流和时间窗口由显式控制节点表达；CEL 只允许出现在显式高级表达式节点或插件自己的专业 DSL 中。

Quant 指标通过闭合 K 线事件驱动，指标节点只保存指标和参数并引用行情 Profile。实时和回测使用同一张下游图，回测只替换入口和回测 Profile。

## 取舍

这是一次破坏性基线切换，不读取或写回 Graph v1/v2，也不提供旧数据转换器。需要回滚时恢复匹配版本的数据库备份和应用镜像。这样可以删除双模型转换层，避免入口、边条件和 Profile 配置在前后端之间发生语义漂移。

## 验收约束

- 修订必须是 `schemaVersion: 3`，且至少包含一个 Trigger 节点。
- 所有节点必须从某个 Trigger 可达，图必须是 DAG。
- Profile 引用必须指向已发布版本；Run 保存修订中已固定的 Profile 引用快照（包含版本）。
- 一个 Trigger 进入 `error` 不得阻止其他 Trigger 创建 Run。
- 不再存在工作流级 `mode`、单一主 Trigger、`entryPoints` 或边条件 CEL。
