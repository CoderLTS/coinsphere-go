# ADR-0007：交易 Realm、权限、账本与凭据

- 状态：接受
- 日期：2026-08-04

## 背景

模拟盘和实盘需要复用订单、成交、风控和账本语义，但必须防止跨环境混写、自动放行和重复下单。Python 回测结果也不能成为实盘账务权威。

## 决策

- 使用共享 schema 和强数据库约束，不引入双 schema 或 RLS。
- `paper/live` realm 只覆盖交易聚合：账户、凭据、权限、Intent、订单、成交、仓位、余额、账本和风控状态。行情、数据集、策略版本和研究结果保持公共。
- Realm 在交易账户上不可变；所有交易实体携带 realm/账户归属并通过复合外键和唯一约束阻止跨 realm 关联。
- Go 使用追加式复式分录作为权威账本；余额和仓位是可重建投影，修正只追加冲正或调整，不建设通用事件溯源平台。
- Python 只输出版本化的非权威回测事实和 Manifest，Go 校验并生成订单、成交、费用、仓位和分录。
- 交易权限使用数据库状态机，绑定账户、策略版本和 R1/R2/R3，支持申请、批准、启用、暂停、撤销和过期。Executor 在产生外部订单前强制校验，环境变量只作第二层总熔断。
- 账户硬风控上限必须逐项显式配置，策略只能相同或更严格；缺少任一限制时保持禁用，不提供隐式数值默认值。
- R2 需要模拟盘至少 30 天和 100 笔完成订单；R3 需要小额现货稳定 30 天，并另完成永续模拟/Testnet 30 天和 100 笔订单。

Web 凭据录入使用浏览器生成的一次性 AES-GCM 数据密钥，并由 Executor 公钥封装。API 只保存信封密文、公开元数据和 `key_id`，不持有可解密私钥。新凭据先验证权限和连通性，再原子切为 active；旧版本进入 retiring，只用于在途订单对账，随后 revoked。

进入 R2 前，构建与生产固定部署器必须分离，部署器只接受已校验的 digest/Manifest，不执行仓库脚本或接触交易密钥。

## 结果

- 模拟和实盘复用同一领域模型，同时由数据库约束、权限状态机和 Executor 身份形成三层边界。
- 交易证据可从不可变分录重建，回测引擎不能直接写权威余额或仓位。
- 首期普通角色仍共用受限数据库身份；如果出现实际越权或多租户需求，再评估更细角色或 RLS。
