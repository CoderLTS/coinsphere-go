# ADR-0001：采用模块化单体与多进程运行边界

- 状态：已接受
- 日期：2026-07-31

## 背景

当前项目是单个 Go 后端和 Vue 前端。未来需要持续行情采集、Python 回测、模拟与实盘执行，但部署目标仍是个人家用 Linux 主机。

## 决策

保持单仓库和模块化单体，Go 领域代码共享同一组强类型契约，并按 `api`、`collector`、`scheduler`、`executor` 进程角色运行。Python Worker 是唯一独立语言边界。任务队列和 Outbox 使用 PostgreSQL 实现。

## 结果

- 获得采集、计算、交易执行之间的进程故障隔离，同时避免微服务网络契约和额外中间件。
- Executor 可以独占交易凭据，API、AI 和工作流不具备直接下单权限。
- 多机扩展前，PostgreSQL 是唯一协调点；出现持续锁竞争或独立扩缩容需求时再编写新 ADR 评估消息中间件。
