# ADR-0009：Binance 行情、单文件策略与双通道 Worker

- 状态：接受
- 日期：2026-08-05

## 背景

旧设计同时规划 Binance/OKX、多个原生数据流、Rootless Docker Launcher、逐任务容器、固定镜像平台和 vectorbt。实际需求只有 Binance Spot/USD-M 的低频闭合 K 线、自定义策略、回测和实时信号；策略代码只由管理员编辑，不是面向不可信租户的执行平台。

## 决策

- V1 只支持 Binance Spot 与 USD-M、交易所原生周期、最低 `1m`。同步全部品种元数据，历史按回测窗口补齐，实时只订阅自选和启用策略需要的数据流。
- `market_candles` 继续作为唯一 K 线 hypertable，使用 7 天 chunk、30 天后压缩和默认两年 retention。闭合 K 线默认冻结，显式修复记录原因和质量事件。
- 策略版本只有一份 Python 文件，固定市场、品种、周期、回看窗口、简单参数 Schema 和运行时。入口统一为 `on_bar(candles, params) -> Decimal`。
- Spot 输出 `0..1`、USD-M 输出 `-1..1` 的归一化目标仓位；回测和实时使用同一入口与校验。
- Python Worker 保持单服务，PostgreSQL 队列固定 `realtime/backtest` 两条通道。Realtime 永久保留一个执行槽；Backtest 只运行一个受限子进程，不能占用实时槽。
- Worker 容器使用固定依赖，不允许运行时安装。任务子进程使用清理环境、墙钟超时和 CPU/内存/空间限制，但不宣称抵御恶意管理员代码。
- 不再启动逐任务 Docker，也不引入 vectorbt、NautilusTrader、自定义镜像、多文件策略包或动态依赖系统。
- 回测使用窄范围 Decimal Bar 模拟器：信号在本 Bar 闭合计算，下一 Bar 开盘成交；覆盖费用、滑点、资金费、保护止损和保守强平，不模拟盘口排队或部分成交。
- 普通回测保存规范化数据哈希；晋级候选使用本地内容寻址 `JSONL.gz + SHA-256 Manifest` 冻结完整输入和结果。

## 结果

- 实时与回测共享最小策略语义，不需要维护两套引擎或容器平台。
- 放弃不可信多租户沙箱和高吞吐回测；管理员代码错误由资源限制、失败暂停和通知约束。
- 若单回测槽或窄模拟器达到可测量上限，再针对具体瓶颈增加并发或成熟引擎，不提前抽象插件层。

## 未采用方案

- 完整 `vectorbt`/NautilusTrader：当前单品种目标仓位语义不需要其大部分能力，资金费和保护单仍需自定义。
- 每任务 Rootless Docker：对可信管理员代码的运维成本高于收益。
- 继续支持 OKX：增加协议、质量和交易验证矩阵，但当前没有实际使用需求。
