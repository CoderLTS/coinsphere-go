# ADR-0002：PostgreSQL 版本化 SQL migration 与冻结点

- 状态：接受
- 日期：2026-08-01
- 修订：2026-08-05，按正式 Paper 观察定义冻结点

## 背景

CoinSphere 只运行 PostgreSQL/TimescaleDB，需要可审查、可复现的 schema 历史。项目尚未开始正式 Paper 观察，未投产数据允许重置；但一旦开始记录 Paper 晋级证据，继续改写历史 migration 会破坏可追溯性。

## 决策

- DDL 只由独立 migration 命令执行；应用启动只读校验版本，不使用 `AutoMigrate`。
- 正式 Paper 观察前允许在明确设计决策下重写、合并或重排历史 migration，但必须重置所有开发和 CI 数据库，不编写旧 schema 或旧数据升级路径。
- 重写既有 migration 只允许整理基线或落实已接受 ADR；不得静默改变公共类型、字段、枚举、规范化和持久化语义，语义变更必须先修订 ADR 与契约。
- 开始记录 Paper 晋级证据前完成最后一次空库重建、Up/Down/重放、基线版本和验证证据记录，并永久冻结全部既有 migration。
- 冻结后只能追加新版本，不得修改、重排或复用已存在版本号。
- Migration 默认随所属纵向能力交付；共享基线、破坏性或跨领域 schema、凭据、风控和订单状态机变更使用独立 PR。
- 每个文件默认在独立事务中执行。无法无损 Down 时明确声明只允许前向演进和备份恢复，不提供伪可逆 SQL。
- 生产发布先完成并验证备份，再执行 Up；代码回滚不得自动执行 Down 或改写 `schema_migrations`。

## 结果

- 投产前可以保持紧凑基线，不承担未投产数据兼容成本。
- Paper 晋级证据开始后获得不可变 migration 历史和确定的恢复边界。
- 任何历史重写都意味着开发/CI 空库重建；若出现需要保留的数据，必须提前进入冻结状态。

## 未采用方案

- 长期允许修改历史 migration：会让不同环境无法证明使用同一 schema。
- 每个 schema 变化都独立 PR：会把纵向能力拆成无法单独使用的内部步骤。
- 支持 SQLite/MySQL 或旧 PostgreSQL schema：当前产品没有该兼容需求。
