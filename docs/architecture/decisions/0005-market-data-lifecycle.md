# ADR-0005：原生多周期行情与 Timescale 生命周期

- 状态：已被 ADR-0009 替代
- 日期：2026-08-04
- 替代日期：2026-08-05

## 背景

A2.0 已冻结 Instrument、Candle、Ticker 和三张普通 PostgreSQL 表，但尚未实现 Store、runner、网络采集、补数、Timescale 生命周期或质量口径。

## 决策

- A2.1 将 `market_candles` 规划为唯一行情 hypertable；Instrument 和最新 Ticker 保持普通表，不新增 Ticker 历史表。
- A2-A5 仍处于 migration 可重整窗口，实施时允许重写 `00003` 并重建开发/CI 空库；A6/R1 前按 ADR-0002 冻结。
- hypertable 使用 7 天 chunk，30 天后压缩，在线保留期可配置且默认 2 年。压缩失败保留未压缩数据并告警；retention 独立重试，失败不影响采集。
- 只长期保护已发布且被引用的 Parquet 数据集，不建设全部过期 K 线的冷归档流水线。
- 同步 Binance/OKX 全部品种元数据，只采集启用集。默认启用两所 BTC/ETH 的 USDT 现货和永续。
- 保存交易所原生 `1m/5m/15m/1h/4h/1d`，日线统一 UTC。WebSocket 实时与 REST 历史/断线补数进入同一规范化和幂等写入路径。
- 未闭合 K 线可更新；闭合 K 线默认冻结，只有显式修复任务可修改，并记录原因和质量事件。
- 各周期以交易所同周期 REST 修复结果为权威；1m 聚合只做交叉检查，差异持久化但不自动覆盖高周期。

完整率按每条 `venue+instrument+interval` 启用流的滚动 30 天分别统计，只包含已闭合且可交易的 UTC 时间槽。每条流必须达到 99.99%，不能用全局平均掩盖缺口。

恢复时间从 Collector 确认连接或心跳失效开始，到重连订阅并成功写入首条规范化事件结束。交易所官方故障单独分类，本地恢复目标为 30 秒。

## 结果

- 保留交易所原生周期，避免自行聚合成为第二事实源；代价是需要跨周期质量检查。
- 在线数据有明确容量上限，已发布研究数据通过不可变数据集长期保留。
- 初始采集规模可控，后续品种必须由用户显式启用。
