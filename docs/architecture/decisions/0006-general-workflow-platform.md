# ADR 0006：通用工作流核心与 SDK 4

状态：已实施。日期：2026-10-05。

替代 ADR 0002 中的量化入口/通用金融 SDK、保存即活动修订、超级管理员工作流管理、旧 schema 与兼容插件升级约束；保留模块化单体、PostgreSQL 队列、编译期可信源码和同进程运行的决策。

## 问题

Core 与通用页面包含金融语义，前端旧图适配损失字段，保存与发布绑在一起。能力从菜单间接授予，插件路由和固定结果范围没有完整契约。租约恢复、Loop 槽位、审批事务、插件引用与升级失败恢复存在执行正确性问题。

## 决策

1. 通用 Graph 3 与 SDK 4；金融契约归 plugin/contracts/trading，逐帧评估归 Quant，通知组合归 Notification，插件拥有 Ingress/Cleanup。
2. 不可变修订与独立 draft/published 指针；原子创建/保存，显式发布，历史保留服从实际引用。
3. 复用 PostgreSQL 队列，有界 Run 预算、周期恢复、租约 fencing、Loop 绝对期限与父子槽隔离。持久状态按修订隔离并串行；审批创建和 waiting 同事务。
4. 独立角色能力加 owner/user/role 资源授权；权限授予上限和事务复验；System/Workflow/Result 三种 Scope 与自定义动作；持久 token 撤销和长连接复验。
5. 单一官方清单，精确安装/编译版本，贡献明确归属，生命周期维护真实引用。普通结果页与运行面板分开；前端直接使用原生模型。
6. 新 Core/插件基线与独立目标库；旧 migration 不变，离线 inspect/plan/apply/verify 迁当前工作流与必要配置，默认 inactive，不迁执行历史、状态或 Live 放行。没有线上兼容层。
7. 一个 PR 同时交付模型、执行、权限、插件、页面、迁移、行为门禁和文档。复用 Go testing、PostgreSQL 16、tsx/Node 和 Playwright，不增加服务或测试框架。

## 代价与限制

插件仍是同进程完全可信代码，不提供沙箱。含持久状态的图以吞吐换取明确串行语义。新增修订采用新的状态命名空间，发布不会继承策略状态。插件升级须处理当前引用，历史图可能无法在新版本执行；这些是本次允许破坏兼容的明确结果。

跨 generation 不执行原地 Up/Down。恢复必须配对数据库、镜像、配置和独占文件；迁移不重放外部副作用，交易恢复由账户人员手工核对。真实环境盘点及启用条件由迁移报告和运维证据确认，代码测试不能替代。
