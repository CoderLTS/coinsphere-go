# ADR-0004：OpenAPI 3.0.3 与原子迁移 /api/v1

- 状态：接受
- 日期：2026-08-04

## 背景

当前管理接口使用手写路由、DTO 和统一 JSON 信封，前端也依赖该旧语义。新增金融接口如果继续手写契约，会让 Go、TypeScript 和文档逐步漂移；长期并存 `/api` 与 `/api/v1` 又会形成无必要兼容层。

## 决策

- OpenAPI 3.0.3 文件是 `/api/v1` 的单一契约来源。
- 使用 `oapi-codegen` 只生成 Go 类型，使用 `openapi-typescript` 生成前端类型；不生成或替换现有 HTTP 路由框架。
- 生成文件随 OpenAPI 一起提交，CI 重新生成并要求无差异；`oasdiff` 比较 PR base 并阻止未声明的破坏性变更。
- A2.3 实施 Issue 必须先盘点全部旧 `/api` HTTP/WebSocket 入口及其请求、响应、Header 和 Cookie 语义，特别覆盖登录、刷新、登出等 Auth/refresh Cookie 路径，清单冻结后才开始迁移。
- 旧管理接口、前端调用、契约和测试在 A2.3 的一个原子纵向 PR 中全部迁移并删除旧 `/api`，不保留兼容层。
- 错误使用 `application/problem+json`；列表使用默认 50、最大 200 的不透明游标，并以唯一 ID 稳定排序。
- 普通异步任务的 `Idempotency-Key` 保留 24 小时。交易命令的键、请求摘要、账户和订单与审计记录同寿命；同键不同载荷返回冲突。

## 结果

- `main` 在迁移前后均保持前后端匹配，不经历半迁移状态。
- 代价是 A2.3 PR 较大，但避免临时兼容层和长期双协议维护。
- 本 ADR 只冻结工具链与语义；OpenAPI 文件和生成代码在 A2.3 实现，不在治理文档 PR 中提前伪造。
